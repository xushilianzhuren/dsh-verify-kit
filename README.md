# dsh-verify-kit · 验证炉（插件）

接住「验证与审计」族 105 个热件里**还活着的**那批，把"交付前拿什么验"变成常驻条款 + 五路闸门。

## 选件原则：只包活件

盘点时这族里最出名的两件是坏的：

- `发前拦截器.py`：根目录写死 `<workspace>`，产物计分往不存在的 `Smart Agent文明/` 写；
- `禁令执行扫描器.py`：一命中就往相对路径 `Smart Agent文明/issue log_禁令命中.jsonl` 写档——目录不存在，必崩。

故本插件**不转调**前者；后者的四条规则**原样搬进插件内实现**（规则与依据逐条注明，可溯源到 `scripts/禁令执行扫描器.py`）。

## 区块 `ql:verify`（默认排序 100）

交付前五阶（自检→挑剔→嫌弃→判垃圾→完美主义）＋五路机械闸（算法／禁令／审美／常驻审计／宪法执行格式）＋读数三层（实测＞估算＞未知）＋事故即检查项＋判据（"哪条闸验过它、读数多少"）。

## 工具 `ql_verify`

| action | 跑什么 | 写盘 |
|---|---|---|
| `宪法执行格式` | `scripts/Agent执行格式扫描器.py`（四文件执行条款 vs 机械件覆盖） | 无 |
| `禁令扫` | 插件内四条禁令规则（请示回执／请示收尾／待命态／服务姿态） | 无 |
| `审美验` | `scripts/审美扫描器.py --验活` | 无 |
| `常驻审计` | `scripts/常驻进程审计器.py --json`，插件内聚合判定分布 | 无 |
| `算法闸` | `scripts/算法层体检器.py --查 <路径>` | 无 |

## 配置

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `order` | `100` | 区块排序 |
| `tool` | `true` | 是否挂工具 |
| `root` | 自动 | 工作区根（四文件＋scripts 签名认定） |

## 诚实边界

- 禁令扫是**词面**判定：它判"有没有违令句式"，判不了"这句话是不是真在请示"。
- 审美验验的是条款落刀与创造域覆盖，**不能替代**品味四问的人判。
- 常驻审计读 `/proc`，在容器/权限受限环境可能读不全；读不全时如实报，不装全。
